# 가림제로 모듈 구조

## 책임 분리

UI는 Tabler Core의 컴포넌트 CSS와 프로젝트 테마를 결합합니다. `src/ui/layout.js`는 작업 헤더·분석 요약을 구성하고, `map-board.js`와 `review-panel.js`는 지도 및 탐색·편집 패널을 독립적으로 렌더링합니다. 지도는 요약 수치보다 먼저 배치하며 모바일 작업 탭은 하단에 플로팅 형태로 표시합니다. Safe Area와 하단 콘텐츠 여백을 함께 확보하고 토스트도 탭 위로 이동합니다. 계산 엔진과 프로젝트 저장 형식은 UI 패키지에 의존하지 않습니다.

## 계산 흐름

1. 사용자가 입력하면 검증된 프로젝트 상태를 변경합니다. 편집 중인 DOM 입력을 교체하지 않습니다.
2. 관찰점·무대·장비 형상에 변화가 있을 때만 분석을 요청합니다. 선택·이름 변경은 계산을 반복하지 않습니다.
3. Coordinator는 실행 중인 작업 1개와 교체 가능한 대기 요청 1개만 유지합니다. 연속 입력은 40ms 동안 병합합니다.
4. Comlink 워커가 관찰점을 캐시하고 계산합니다. 입력이 바뀌면 현재 작업을 취소합니다. 결과는 요청 버전이 현재 상태와 같을 때만 적용합니다.
5. 워커가 실패하거나 응답 제한을 넘기면 분할 계산으로 전환합니다. 약 192개 관찰점마다 scheduler.yield/MessageChannel/타이머로 다음 이벤트에 실행 기회를 줍니다.
6. 보고서는 최신 분석 완료를 기다린 뒤 결과를 가져옵니다. 계산 중에도 프로젝트와 장비 입력은 계속 사용할 수 있습니다.

## 렌더링과 공간 검색

기본 화면은 `src/rendering/seat-map.js`의 SVG 지도입니다. 공개 관찰점 X/Z 좌표에서 d3-polygon으로 외곽을 계산하고, 관찰점을 색상별 복합 경로로 묶어 수천 개의 DOM 노드를 만들지 않습니다. 경계 채움은 탐색을 위한 시각적 안내이며 실제 벽·좌석 구역을 복원한 형상이 아닙니다. 클릭 위치는 SVG 좌표로 변환해 가장 가까운 관찰점으로 연결합니다.

지도는 기준안·현재안·변화를 전환합니다. 변화는 동일 ID의 가림 표본 수를 비교해 감소·증가·동일을 구분합니다. 오른쪽 선택 영역의 변화 수는 해당 영역의 동일 관찰점 집합에 한정하며, 아래 전체 지표는 선택한 배치의 전체 집합을 표시합니다. 보고서는 현재안 지도를 별도로 생성해 기준안 미리보기 이미지와 현재안 수치가 섞이지 않도록 합니다.

`src/data/demo-project.json`은 공개 관찰점에 대해 추천 기준을 적용한 가상 배치 예제입니다. `scripts/generate-demo.mjs`로 재현할 수 있습니다. 기존 저장값이 없을 때만 처음 열리며, 기존 프로젝트를 덮어쓰지 않습니다. 예제 버튼으로 불러온 경우 변경 취소 이력에 이전 프로젝트를 보관합니다. 지도와 3D 보기를 전환하며 3D는 현재안만 편집합니다.

3D 보기의 기본 표시는 공개 관찰점·무대·장비만 남기는 간단 시야도입니다. 임의의 원형 관람석 표면과 격자, 교차하는 시선 9개를 그리지 않습니다. 원본 건물 모델은 선택했을 때만 표시하며 배경 로딩이 끝나도 간단 보기와 카메라 위치를 바꾸지 않습니다. 전체 보기는 관찰점 경계와 화면 종횡비로 카메라 거리를 계산해 좁은 화면에서도 관찰점이 잘리지 않게 맞춥니다.

탐색 화면은 넓은 공연장 뷰포트와 한쪽 도구 패널로 구성합니다. 영역은 관찰점과 무대 중심 사이 X/Z 방향으로 맞은편·뒤편·왼쪽·오른쪽을 나누며 공식 좌석 구역이 아닙니다. 영역 선택은 관찰점 강조와 별도 요약에만 적용합니다. 전체 통계·보고서·위치 후보 비교의 분석 대상은 유지합니다. 관객 시점 진입은 선택 영역의 관찰점 평균 좌표에 가장 가까운 실제 관찰점을 사용합니다.

공식 GLB에는 조명용 법선 속성이 없어 로딩 시 누락된 법선을 계산한 뒤 조명 재질을 적용합니다. 공연장은 불투명한 밝은 표면으로, 무대는 어두운 면과 앞쪽 강조선으로 표시합니다. 관찰점은 실제 눈높이 좌표에 작은 원판으로 표시하고 깊이 테스트를 적용해 건축물을 관통해 보이던 표시를 줄입니다. 시각적 건축물 가림과 추가 장비만 계산하는 수치 분석의 범위는 구분합니다.

장비는 ID별 객체, 무대는 단위 박스를 유지하며 transform만 바꿉니다. 관찰점은 InstancedMesh를 재사용하며 위치가 같으면 색상만 갱신합니다. 관찰점 수가 증가해 용량을 초과할 때만 버퍼를 확장합니다. 삭제·교체 시 geometry/material을 해제합니다.

OrbitControls 변화, 장비 이동, 분석 결과, 창 크기 변경 때 프레임을 요청합니다. 정지 화면에서 전체 공연장을 계속 렌더링하지 않습니다. WebGL 컨텍스트 손실·복구 상태를 표시하며 Three.js의 복구 처리를 이용합니다.

큰 공식 mesh의 BVH는 원본 geometry의 복사본을 워커로 보내 생성합니다. 실패해도 원본 버퍼가 분리되지 않으므로 일반 picking으로 돌아갈 수 있습니다. 모델이 준비되기 전에는 개략도를 유지합니다.

## 저장과 검증

idb-keyval로 350ms 지연·병합 저장하며 쓰기 순서를 직렬화합니다. 탭 종료·숨김 시 작은 프로젝트 스냅샷을 localStorage에 남기고, 복원 때 두 저장소 중 최신 savedAt을 선택합니다. 사용자 모델 바이너리는 프로젝트 JSON에 포함하지 않습니다.

검증에는 실제 Worker RPC와 주 스레드 heartbeat, 최신 요청 경쟁, 강제 워커 종료 후 fallback, 분석 커널·Three.js 교차 비교, geometry 참조 재사용·dispose, IndexedDB 왕복을 포함합니다. 브라우저 WebGL 프레임 속도는 별도 수동 검증이 필요합니다.
