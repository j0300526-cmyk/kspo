# 가림제로 · 공연장 시야 편집기

한국체육산업개발의 공개 KSPO DOME 공간 모델을 활용한 공연 장비 배치·시야 가림 분석 웹앱입니다.

[배포 앱 열기](https://garim-zero-kspo-studio.hanwonjun.chatgpt.site) · [데이터 활용·변환 기록](docs/venue-data.md) · [모듈 구조](docs/architecture.md) · [배포 검증 기록](docs/verification.md)

배포 앱은 현재 소유자 전용으로 운영합니다. 접근 권한이 있는 ChatGPT 계정으로 로그인해야 합니다. 소스는 이 저장소에서 내려받아 로컬에서 실행할 수 있습니다.

## 실행

Node.js 22.12 이상 또는 24에서:

```powershell
git clone https://github.com/j0300526-cmyk/kspo.git
cd kspo
npm ci
npm run dev
```

표시되는 로컬 주소를 브라우저에서 엽니다. 변환된 모델과 관찰점이 저장소에 포함되어 있어 API 키나 별도 데이터 다운로드가 필요하지 않습니다. 모델은 약 18.5MB이므로 처음 열 때 로딩 시간이 필요합니다.

| 명령 | 용도 |
| --- | --- |
| `npm run dev` | 로컬 개발 서버 |
| `npm test` | 분석·상태·저장·워커·모델 자동 검증 |
| `npm run build` | `dist/`에 정적 배포 파일 생성 |
| `npm run preview` | 빌드 결과 로컬 확인 |
| `npm run format` | 소스와 테스트 코드 포맷 정리 |

## 사용 흐름

화면은 [Tabler Core](https://github.com/tabler/tabler)의 오픈소스 컴포넌트를 사용합니다. 지도를 먼저 표시하고 전체 분석 요약은 아래에 배치합니다. 밝은 헤더와 파란색 주요 버튼, 모바일 플로팅 작업 탭, Safe Area 여백을 적용했습니다. 안내와 저장·오류 메시지는 해요체로 작성하고 버튼에는 실제 수행 동작을 표시합니다. 사용자 제공 앱인토스 UI/UX 가이드의 웹에 적용 가능한 원칙을 참고했으며, 앱인토스 입점·SDK 연동 또는 검수 승인을 의미하지 않습니다. 그래픽과 브랜드는 자체 자료 및 기존 오픈소스 아이콘을 사용합니다.

첫 화면은 공개 관찰점 좌표를 이용한 **공연장 지도와 배치 전후 비교**입니다. 처음 실행할 때는 가상 장비 배치 예제를 표시하며, 기존에 저장한 프로젝트가 있으면 그대로 복원합니다. ‘예제 불러오기’로 비교 사례를 불러올 수 있습니다. 지도에서 기준안·현재안·변화 보기를 전환하고 개별 관찰점의 가시 표본을 비교할 수 있습니다. 원본 건물과 관객 시점은 3D 보기에서 확인합니다. 예제는 `node scripts/generate-demo.mjs`로 같은 공개 관찰점과 추천 기준에서 재생성할 수 있습니다.

1. ‘관람 위치 탐색’에서 전체·무대 맞은편·평면도 왼쪽/오른쪽·무대 뒤편을 고릅니다. 선택 영역의 관찰점과 평균 가시율을 확인합니다. 이 영역은 무대 좌표 기준 방향 분류이며 공식 좌석 구역이 아닙니다.
2. 관찰점을 선택해 기준안·현재안의 가시 표본 수를 비교합니다. ‘이 영역에서 관객 시점 보기’를 누르면 3D 관객 시점으로 전환합니다. 관찰점 데이터와 사용자 모델은 ‘관찰점·모델 설정’에서 변경합니다.
3. ‘무대·장비 편집’에서 무대와 장비를 편집하고 위치 후보를 비교합니다. 지도 아래 수치와 보고서·기준안 비교는 전체 관찰점 기준이며, 영역 요약은 선택 영역 기준입니다.
4. 프로젝트 JSON, 지도 SVG 또는 3D 화면 PNG, 관찰점별 CSV 및 인쇄/PDF용 분석 보고서를 내보냅니다.

## 구현된 기능

- 공식 DAE를 변환한 18.5MB GLB 로딩. 지붕 상부를 숨겨 내부 배치를 표시합니다.
- 의자 형상에서 추출한 7,382개 관찰점, 504개 개략 표본, 직접 지정 관찰점 모드.
- 카메라 플랫폼·스피커 타워·콘솔·스크린 추가, 이름/위치/크기/회전 변경과 삭제.
- 3D 장비 드래그 이동, 평면 보기, 관찰점 선택, 관객 시점, 분석 색상 전환.
- 엔드/센터 스테이지와 무대 크기·위치·높이·관찰 대상 높이 설정.
- 회전된 장비 상자와 유한 시선 선분의 교차 계산. 무대의 3×3 표본에 대해 가림율을 산출합니다.
- 선택 장비에 대한 위치 후보 탐색. 평균 가시율이 높아져도 가림 발생 수나 50% 이상 가림 수가 늘어나는 후보는 추천에서 제외합니다. 기준안 대비 세 지표를 함께 비교합니다.
- 변경 취소, 브라우저 자동 저장, JSON 프로젝트 입출력.
- PNG 화면 저장, 관찰점별 CSV 내보내기, 인쇄/PDF용 보고서.
- 사용자 GLB/단일 DAE 모델 로딩. 외부 텍스처/별도 버퍼 파일은 포함하지 않으며 모델 단위는 미터로 준비해야 합니다. 사용자 모델 파일은 JSON에 포함되지 않습니다.
- 한국어 인터페이스 및 좁은 화면에서의 세로 레이아웃.

| 반복 의자 부품 형상 | 중복을 제거한 7,382개 관찰점을 추출해 추가 장비의 시야 가림 계산에 사용 |

## 데이터 요청과 분석 호출

현재 버전은 정적 웹앱입니다. **기관의 실시간 REST API나 별도 앱 서버 API를 호출하지 않습니다.** 공개 파일을 내려받아 변환한 데이터를 같은 배포 주소에서 읽고, 분석은 사용자 기기의 Web Worker에서 실행합니다.

| 요청 경로 | 응답·역할 |
| --- | --- |
| `/models/observation-points.json` | 관찰점 ID와 좌표 JSON |
| `/models/venue-meta.json` | 모델 변환·공간 메타데이터 JSON |
| `/models/kspo-dome.glb` | 공연장 3D 바이너리 |
| `/assets/*.js`, `/assets/*.css` | 앱 코드·스타일·지연 로더·계산 워커 |

분석 워커는 Comlink를 통해 `ping`, `setObservers`, `analyze`, `optimize`, `cancel`을 제공합니다. 이 호출은 브라우저 내부 RPC이며 HTTP API 주소가 아닙니다. 프로젝트는 브라우저에 저장하며 서버로 전송하거나 기기 간 동기화하지 않습니다.

## 해석 범위

**입력한 추가 장비의 가림을 비교하는 설계 참고 도구입니다.** 관찰점 ID는 공식 좌석번호가 아닙니다. 반복 부품에서 추출한 위치와 등받이 위 0.30m의 눈높이 가정을 사용합니다. 추출한 관찰점은 전체 좌석을 완전히 복원한 집합이 아닙니다. 공개 모델 작성 메타데이터는 2023년 1월이며 현재 공연 배치와 다를 수 있습니다.

기존 건축물·난간·관객·실제 카메라 모양·LED 영상의 가림과 음향은 계산하지 않습니다. 장비 시각화의 장식용 카메라 헤드는 계산용 상자에 포함되지 않습니다. 무대 뒤쪽 관찰점도 포함하며 공연자 정면 여부를 판정하지 않습니다. 전체 공연장 수용인원/실제 시야제한석 수를 뜻하지 않습니다.

배치 개선은 단순 장비·무대 상자 겹침을 피하는 위치 후보 탐색입니다. 출입구·동선·소방·하중·시공 가능성에 대한 검토를 대체하지 않습니다. 로컬 실행에는 서버 계정·유료 API가 필요하지 않습니다. 프로젝트 설정은 IndexedDB에 비동기로 저장됩니다. 저장소를 사용할 수 없을 때는 localStorage로 전환하며, 탭을 숨기거나 닫을 때 복구용 스냅샷을 기록합니다. 글꼴은 운영체제의 기본 글꼴을 사용합니다.

## 모듈 구조와 응답성

실행 진입점은 `src/main.js`이며 역할별 구조는 [docs/architecture.md](docs/architecture.md)에 정리했습니다. 시야 계산과 위치 후보 비교는 Comlink Web Worker에서 실행합니다. 연속 입력은 최신 요청으로 병합하고 오래된 결과는 적용하지 않습니다. 워커가 실패하면 작업을 작은 묶음으로 나눠 화면에 실행 시간을 양보하는 방식으로 전환합니다.

Three.js 객체는 위치·크기·색상을 갱신하며 재사용합니다. 뷰포트는 변경된 프레임에만 렌더링하고 배경 탭에서는 멈춥니다. 공식 모델 클릭 검색은 three-mesh-bvh로 가속하며 검색 구조 생성도 별도 워커에서 수행합니다. 3D 로더는 지연 로딩하여 편집 UI가 먼저 시작됩니다.

## 검증

현재 자동 테스트는 24개입니다. 관람 영역 분류·대표 관찰점 선택·탭 이동과 모델 법선 준비 검증을 포함합니다. 2026년 11월 24일(KST) 초기 배포본 점검에서는 인증 HTTP 요청 10건이 모두 200을 반환했고, 관찰점 7,382개와 모델 메시 91개를 읽었습니다. 내려받은 분석 워커 코드로 분석과 위치 후보 비교를 실행했습니다. 당시 검사 대상 커밋·수치·범위는 [배포 검증 기록](docs/verification.md)에 있습니다.

`npm test`는 시선-장비 교차, 회전, 장애물 없는 결과, 입력 검증, 원본 설정 보존, 실제 GLB 파싱, 관찰점 데이터, 기본 배치 개선을 검증합니다. 추가로 실제 Node Worker/Comlink 실행 중 메인 이벤트 루프가 진행되는지, 워커 종료 후 복구, 취소·최신 요청 처리, 객체 재사용·해제, BVH 교차 결과, IndexedDB 저장·복구를 확인합니다. Happy DOM 기반 앱 테스트는 관찰점 로딩→장비 수정→변경 취소→기준안 비교→보고서와 빈 관찰점 처리를 검증합니다. 이 테스트의 3D 렌더러는 대역이며 브라우저 WebGL·실제 FPS 검증과 구분합니다.

## 배포

`npm run build` 후 정적 호스팅에 `dist/` 전체를 게시합니다. `index.html`뿐 아니라 `assets/`, `models/`, `licenses/`와 지연 로더·워커 파일도 함께 배포해야 합니다. 런타임 환경변수나 API 키는 사용하지 않습니다.

현재 배포는 ChatGPT Sites를 사용하며 설정은 [`.openai/hosting.json`](.openai/hosting.json)에 있습니다. **GitHub 푸시만으로 자동 배포되는 CI는 아직 구성하지 않았습니다.** 소스를 저장한 커밋과 해당 빌드의 배포 아카이브를 Sites에 등록해 게시합니다. 다른 Sites 프로젝트를 새로 만들 때는 새 프로젝트의 ID로 설정해야 합니다.

Windows에서 기본 패키저의 디렉터리 정리 단계가 제한되는 경우, 빌드 후 다음 명령으로 삭제 없는 새 staging 폴더에 배포 파일을 모을 수 있습니다. 경로는 존재하지 않는 새 아카이브 파일을 지정해야 합니다.

```powershell
powershell -NoProfile -File scripts/package-windows.ps1 -ArchivePath C:/temp/garim-zero-deploy.tar.gz
```
