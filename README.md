# 가림제로 · 공연장 시야 편집기

한국체육산업개발의 공개 KSPO DOME 공간 모델을 활용한 공연 장비 배치·시야 가림 분석 웹앱입니다.

## 실행

Node.js 22.12 이상 또는 24에서:

```powershell
npm ci
npm run dev
```

표시되는 로컬 주소를 브라우저에서 엽니다. 배포 파일 생성은 `npm run build`, 검증은 `npm test`입니다.

## 구현된 기능

- 공식 DAE를 변환한 18.5MB GLB 로딩. 지붕 상부를 숨겨 내부 배치를 표시합니다.
- 의자 형상에서 추출한 7,382개 관찰점, 504개 개략 표본, 직접 지정 관찰점 모드.
- 카메라 플랫폼·스피커 타워·콘솔·스크린 추가, 이름/위치/크기/회전 변경과 삭제.
- 3D 장비 드래그 이동, 평면 보기, 관찰점 선택, 관객 시점, 시선 표시, 분석 색상 전환.
- 엔드/센터 스테이지와 무대 크기·위치·높이·관찰 대상 높이 설정.
- 회전된 장비 상자와 유한 시선 선분의 교차 계산. 무대의 3×3 표본에 대해 가림율을 산출합니다.
- 선택 장비에 대한 위치 후보 탐색. 기준안 대비 평균 가시율과 가림 발생 관찰점 수 비교.
- 변경 취소, 브라우저 자동 저장, JSON 프로젝트 입출력.
- PNG 화면 저장, 관찰점별 CSV 내보내기, 인쇄/PDF용 보고서.
- 사용자 GLB/단일 DAE 모델 로딩. 외부 텍스처/별도 버퍼 파일은 포함하지 않으며 모델 단위는 미터로 준비해야 합니다. 사용자 모델 파일은 JSON에 포함되지 않습니다.
- 한국어 인터페이스 및 좁은 화면에서의 세로 레이아웃.

## 데이터 활용

데이터 목록을 표시하는 데 그치지 않고, 원본 좌표를 미터·Y-up으로 변환한 실제 공연장 형상을 표시합니다. 원본의 반복 의자 부품에서 관찰점을 추출해 장비 가림 분석에 사용하고, 사용자가 공식 모델 표면을 클릭해 관찰점을 추가할 수도 있습니다.

- 데이터셋: [한국체육산업개발_올림픽공원 공연장 실감형 콘텐츠](https://www.data.go.kr/data/15127487/fileData.do)
- 원본 파일: [KSPO DOME DAE ZIP](https://www.ksponco.or.kr/attachFiles/download/kspo/kspodome_dae.zip)
- 변환 과정·가정·해시: [docs/venue-data.md](docs/venue-data.md)

## 해석 범위

**입력한 추가 장비의 가림을 비교하는 설계 참고 도구입니다.** 관찰점 ID는 공식 좌석번호가 아닙니다. 반복 부품에서 추출한 위치와 등받이 위 0.30m의 눈높이 가정을 사용합니다. 추출한 관찰점은 전체 좌석을 완전히 복원한 집합이 아닙니다. 공개 모델 작성 메타데이터는 2023년 1월이며 현재 공연 배치와 다를 수 있습니다.

기존 건축물·난간·관객·실제 카메라 모양·LED 영상의 가림과 음향은 계산하지 않습니다. 장비 시각화의 장식용 카메라 헤드는 계산용 상자에 포함되지 않습니다. 무대 뒤쪽 관찰점도 포함하며 공연자 정면 여부를 판정하지 않습니다. 전체 공연장 수용인원/실제 시야제한석 수를 뜻하지 않습니다.

배치 개선은 단순 장비·무대 상자 겹침을 피하는 위치 후보 탐색입니다. 출입구·동선·소방·하중·시공 가능성에 대한 검토를 대체하지 않습니다. 서버·유료 API·계정이 필요하지 않으며 프로젝트 설정은 IndexedDB에 비동기로 저장됩니다. 저장소를 사용할 수 없을 때는 localStorage로 전환하며, 탭을 숨기거나 닫을 때 복구용 스냅샷을 기록합니다. 글꼴은 운영체제의 기본 글꼴을 사용합니다.

## 모듈 구조와 응답성

실행 진입점은 `src/main.js`이며 역할별 구조는 [docs/architecture.md](docs/architecture.md)에 정리했습니다. 시야 계산과 위치 후보 비교는 Comlink Web Worker에서 실행합니다. 연속 입력은 최신 요청으로 병합하고 오래된 결과는 적용하지 않습니다. 워커가 실패하면 작업을 작은 묶음으로 나눠 화면에 실행 시간을 양보하는 방식으로 전환합니다.

Three.js 객체는 위치·크기·색상을 갱신하며 재사용합니다. 뷰포트는 변경된 프레임에만 렌더링하고 배경 탭에서는 멈춥니다. 공식 모델 클릭 검색은 three-mesh-bvh로 가속하며 검색 구조 생성도 별도 워커에서 수행합니다. 3D 로더는 지연 로딩하여 편집 UI가 먼저 시작됩니다.

## 검증

`npm test`는 시선-장비 교차, 회전, 장애물 없는 결과, 입력 검증, 원본 설정 보존, 실제 GLB 파싱, 관찰점 데이터, 기본 배치 개선을 검증합니다. 추가로 실제 Node Worker/Comlink 실행 중 메인 이벤트 루프가 진행되는지, 워커 종료 후 복구, 취소·최신 요청 처리, 객체 재사용·해제, BVH 교차 결과, IndexedDB 저장·복구를 확인합니다. Happy DOM 기반 앱 테스트는 관찰점 로딩→장비 수정→변경 취소→기준안 비교→보고서와 빈 관찰점 처리를 검증합니다. 이 테스트의 3D 렌더러는 대역이며 브라우저 WebGL·실제 FPS 검증과 구분합니다.

Windows에서 기본 패키저의 디렉터리 정리 단계가 제한되는 경우, 빌드 후 다음 명령으로 삭제 없는 새 staging 폴더에 배포 파일을 모을 수 있습니다. 경로는 존재하지 않는 새 아카이브 파일을 지정해야 합니다.

```powershell
powershell -NoProfile -File scripts/package-windows.ps1 -ArchivePath C:/temp/garim-zero-deploy.tar.gz
```
